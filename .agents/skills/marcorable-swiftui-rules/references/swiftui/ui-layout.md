
# UI 역할과 소유권

UI 타입의 위치와 묶음은 프로젝트 규모, 화면 흐름, 모듈 경계와 기존 구조에 맞춰 결정한다.

## 새 구조의 기본값

기존 관습이 없는 새 앱이나 새 UI 모듈은 역할을 드러내는 `Screens`, `Components`, `Util` 경계를 기본으로 한다.

- 화면 폴더는 어떤 화면이 띄우는지가 아니라 표시 단위 자체를 기준으로 평평하게 둔다
- 한 화면 전용 타입은 해당 Screen이 소유하고, `Subview`처럼 의미가 없는 공용 묶음을 만들지 않는다
- 여러 화면에서 실제로 재사용될 때만 `Components`로 승격한다
- 기존 프로젝트를 이 기본값에 맞추기 위한 이동은 별도 작업으로 다룬다

## 공용 UI 유틸리티

여러 UI 타입에 같은 기능을 부여하는 프로토콜, modifier와 `FormatStyle` 같은 표시 기반 타입은 공용 UI로 취급한다.

## 화면

화면은 push, sheet, fullScreenCover, 탭 콘텐츠, 앱 루트처럼 **표시 단위로 띄워지는 View**다.

- `<Name>Screen` 네임스페이스와 중첩 타입으로 만든다
- 화면 전환과 데이터 저장 같은 화면 시나리오를 소유한다

## 컴포넌트

컴포넌트는 **두 화면 이상에서 쓰고, 값과 클로저만 받는** 표현 View다. 특정 화면의 상태 컨테이너나 action 타입을 모른다.

- 컴포넌트의 부속 View는 그 컴포넌트 안에 중첩한다 — `NoteList.Row`
- 사용자 동작은 클로저로 알린다. 화면 전환이나 데이터 저장은 컴포넌트가 하지 않고 화면이 한다

## 화면 전용 서브뷰

다른 화면에서 함께 쓰지 않으면 그 화면의 중첩 서브뷰다. 화면의 타입을 모르는 View라도 한 화면에서만 쓰면 컴포넌트로 빼지 않는다. 두 번째 화면에서 쓰게 될 때 공용 컴포넌트로 옮긴다.

View가 아닌 타입도 같다. 재생 속도 `Speed`를 재생 패널에서만 쓰면 `ConversationDetailScreen.PlaybackPanel.Speed`로 중첩한다. 여러 화면이 함께 쓰는 값만 화면 밖에 둔다.

새 파일을 나눌 때는 `<부모>.<역할>.swift`처럼 소유 관계가 드러나는 이름을 기본으로 하되, 저장소에 확립된 이름 규칙이 있으면 그것을 따른다.

## 이름

- View 타입 이름에 `View` 접미사를 붙이지 않는다 — `NoteList`, `TabBar`, `Row`
- 화면은 `<Name>Screen.Root`로 쓴다
- 목록과 빈 상태를 함께 보여주는 묶음은 `Board`로 짓는다
- 녹음·재생처럼 미디어 상태를 조작하는 고정 영역은 `Panel`로 짓는다
