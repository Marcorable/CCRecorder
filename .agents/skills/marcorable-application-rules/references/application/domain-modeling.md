
# Domain 모델 경계

- Domain 타입에는 사용자가 다루는 값과 업무 규칙만 둔다
- 저장 매크로, DTO 코딩 키처럼 외부 기술을 위한 선언은 넣지 않는다
- `id`, 생성일처럼 저장 방식과 무관하게 제품에서 의미가 있는 값은 Domain에 둔다
- 레이어 사이에 전달하는 Entity는 값 타입을 기본으로 하되, 동일성과 변경 의미가 필요하면 그 이유에 맞는 타입을 선택한다
- 생성 입력과 완성된 Entity의 의미가 다르면 `Content`, `Draft`, `Command`처럼 의도를 드러내는 입력 타입으로 구분한다
- Data가 Entity를 복원할 수 있는 생성 경로를 제공하되, 저장 기술 때문에 Domain의 불변 조건을 약화하지 않는다

화면 전용 표시 문구와 일시적인 UI 상태는 Domain 모델에 넣지 않는다.
