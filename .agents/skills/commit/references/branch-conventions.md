# 브랜치와 특수 커밋 형식

저장소 규칙이나 기존 이력이 아래 형식을 사용하는 경우에만 적용한다.

## 이슈 브랜치

Marco의 기본 브랜치는 이슈 번호를 중심으로 짓는다. `feature`, `refactor` 같은 작업 종류는 브랜치가 아니라 PR 제목에서 표현한다.

```text
427           단일 이슈
406/parent    하위 PR이 모이는 상위 이슈
406/427       406의 하위 이슈 427
```

Git은 `406`과 `406/427` 브랜치를 함께 만들 수 없으므로 하위 이슈가 생길 상위 브랜치는 처음부터 `<번호>/parent`로 만든다.

이슈 prefix는 자기 이슈 번호 하나만 사용한다.

| 브랜치 형태 | prefix |
|---|---|
| `<issue>` | `[#<issue>]` |
| `<parent>/parent` | `[#<parent>]` |
| `<parent>/<child>` | `[#<child>]` |
| 숫자가 없는 기본·기능 브랜치 | 생략 |

앞에 type이나 epic 경로가 붙은 기존 브랜치는 마지막 작업 번호를 우선하되, parent 표기가 있으면 parent 번호를 사용한다. 숫자가 여러 개이고 자기 이슈를 확정할 수 없으면 사용자에게 확인한다.

## 리뷰와 QA

- 리뷰 반영 커밋을 `Code Review N`으로 관리하는 저장소에서는 같은 브랜치의 이전 번호 다음 값을 사용한다.
- QA 티켓 제목을 커밋 요약으로 보존하는 저장소에서는 제목을 임의로 축약하지 않는다.
- 두 형식 모두 저장소 규칙이나 기존 이력으로 확인되지 않으면 일반 `fix: 요약` 형식을 사용한다.
