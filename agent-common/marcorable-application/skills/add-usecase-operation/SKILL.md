# Usecase 동작 하나 추가

먼저 `../../rules/application/usecase.md`와 Domain 규칙을 읽는다.

## 입력

- 동작의 업무 목적과 완료 조건
- 필요한 Repository 계약
- 입력, 결과와 실패 의미

## 수행

1. 정책, 조합 또는 트랜잭션 경계가 실제로 필요한지 확인한다.
2. 화면 이름이 아니라 수행하는 동작으로 이름을 정한다.
3. 의존성을 명시적으로 주입하고 외부 기술 타입을 노출하지 않는다.
4. 아래 레이어 오류를 호출자가 이해할 수 있는 의미로 변환한다.
5. 업무 규칙과 실패 경로를 단위 테스트로 문서화한다.

## 제외

- 단순 pass-through Usecase를 만들지 않는다.
- API와 Repository 구현을 임의로 확장하지 않는다.
- 화면 문구, loading과 navigation 정책을 넣지 않는다.

## 결과와 검증

- Presentation에서 호출할 수 있는 하나의 독립적인 업무 동작을 남긴다.
- 목적을 이룬 경우와 이루지 못한 경우를 각각 검증한다.
