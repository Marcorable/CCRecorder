# QA 이슈 수정

범위는 **수정까지**다. 커밋은 사용자가 요청할 때 `/commit` 으로 한다.

## 1. 티켓 읽기

```bash
gh issue view <번호> --comments
```

다음을 몇 줄로 정리해 보여준다.

- 화면 경로 — 제목의 `>` 구분 경로 (예: `마이 페이지 > 마트 정보 > 배달 정보`)
- 기대 동작과 실제 동작
- 첨부 근거 — 스크린샷, Figma, 기획서

내용이 모호하면 추측하지 말고 묻는다.

## 2. 원인 찾기

- 증상이 보이는 곳에서 시작해 데이터가 온 쪽으로 내려간다 (화면 → 상태 → 도메인 → API 응답)
- 원인을 한두 문장으로 설명하고 수정 방향을 제안한다

## 3. 수정

- **티켓 범위만 고친다.** 근처 리팩터링은 제안만 한다
- 같은 원인이 다른 화면에도 있으면 알려주고 함께 고칠지 묻는다
- 문구를 고쳤으면 오탈자를 다시 본다
