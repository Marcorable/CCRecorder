# Source of Truth 하나로 전환

## 입력

- 전환할 Aggregate 또는 기능 경계
- 준비된 새 계약과 구현
- 기존 읽기·쓰기 진입점
- 기존 데이터의 호환·migration 방식
- 실패 시 되돌릴 수 있는 경계

## 1. 전환 전 점검

1. 기존 읽기, 생성, 수정, 삭제, 캐시 갱신과 background 작업을 검색해 표로 정리한다.
2. 새 경계가 각 동작과 실패 의미를 대체할 준비가 됐는지 확인한다.
3. 기존 데이터가 그대로 복원되는지, backfill이나 schema migration이 필요한지 검증한다.
4. 전환 실패 시 되돌릴 코드·데이터 경계와 삭제를 미룰 이전 경로를 정한다.

## 2. 전환

1. 관련 읽기와 쓰기를 하나의 검증 가능한 단위로 새 경계에 연결한다.
2. dual-write는 기본적으로 사용하지 않는다. 불가피하면 기간, 정본, 불일치 탐지와 제거 조건을 먼저 명시한다.
3. 이전 경로가 더 이상 원본으로 쓰이지 않게 제거하거나 읽기 전용 호환 경로로 제한한다.
4. 이전 구현의 참조를 검색해 의도한 호환 지점 외에 남지 않았는지 확인한다.

## 3. 검증

1. 기존 데이터가 있는 상태와 빈 상태에서 앱을 실행한다.
2. 생성·조회·수정·삭제와 앱 재실행 뒤 결과를 확인한다.
3. background 갱신, 캐시와 실패 복구처럼 별도 진입점이 있으면 같은 경계를 사용하는지 확인한다.
4. 오류가 나면 정해 둔 경계까지만 되돌리고 데이터 손실 여부를 기록한다.

## 제외

- 준비되지 않은 새 계약을 임의로 설계하지 않는다.
- 인접 Aggregate까지 범위를 넓히지 않는다.
- 구·신 저장소를 동시에 원본으로 남기지 않는다.
- 검증되지 않은 migration 뒤 이전 데이터를 바로 삭제하지 않는다.

## 결과와 검증

- 선택한 범위에는 하나의 Source of Truth만 남는다.
- 읽기와 쓰기가 같은 경계를 사용한다.
- 기존 데이터, 새 데이터와 앱 재실행 경로가 검증됐다.
- 남은 호환 경로에는 제거 조건과 정본이 명시됐다.
